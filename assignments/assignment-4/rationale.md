# Rationale 

I chose the Open Library API. It tells a story about books with a particular title. Users can clicked "Expand Details" to see the author and year if desired. My normalization function protects my rendering code by providing a default option in the event that an attribute is not present. This is done by using || and a default string. Without this, the data could be blank or there might be some other issue. An example error path is when the user presses the search button without typing anything in the search bar. An if statement within the handleSubmit function checks whether the title exists and displays an error asking for the title if it does not exist. If I were building this for a real audience, I would add an image of the book cover using the Open Library ID. This API does support cross-origin requests, but the other APIs at Open Library do not. The rate limit is one request per second, which is plenty for this project. Attribution is not required to use the API. The data can come with an irregular schema occasionally, which is why the normalizeBooks() function exists. Overall, I thought this was a good API choice.
