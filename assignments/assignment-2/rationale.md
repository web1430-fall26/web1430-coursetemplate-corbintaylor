# Rationale

I built a calculator that determines the total bill for a meal, including the tip. It also displays the amount each person owes. It is built for anyone that attends restaurants and wants a quick way to calculate the total bill and amount that each person owes. I separated the calculation logic from the render logic by using separate functions for each. A good example of this is in my `validInputs()` function. For each possible incorrect input, it calls a separate function to display an error message before returning false. This separation matters because functions should have one purpose. Functions that have one purpose are also easier to fix if there are errors. My validation catches strings and blank inputs and displays an error message. Initially, I hadn't thought about blank inputs, so I had to go back and fix that. If I extended this tool, I would add a cash calculator as well that would tell the user exactly what bills and coins are needed for each person's share.
