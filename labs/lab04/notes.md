# Process Reflection

I used a guard clause when rendering the table. Without it, invalid increment values and row counts could be provided, causing the table not to render correctly (row counts past 20 or impossible increment values, such as zero). The clauses also allowed me to display an error message to alert the user of what went wrong. When I tested with out-of-range or missing inputs, the error messages displayed. To add a fourth trail difficulty, I would have to create an new option in the HTML `<select>` and make sure there are trails with that difficulty. I would also have to update `validateInputs()` to check for the new difficulty so that it doesn't get flagged as invalid input.
